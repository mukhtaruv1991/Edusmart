## قاعدة البيانات

تم تثبيت استخدام قاعدة Firestore الافتراضية `(default)` في `src/lib/firebase.ts`، وإزالة الاعتماد على أي `firestoreDatabaseId` أو معرّف قاعدة مخصص. كما تم التحقق من عدم وجود مراجع `databaseId` متبقية داخل `src` وملفات إعداد المشروع.

> يجب أن تكون قاعدة Firestore الافتراضية موجودة في مشروع Firebase `mukhtaruv`، وأن تكون قواعد `firestore.rules` منشورة حتى تعمل عمليات القراءة والكتابة الفعلية.

## التطوير المنفذ

تم استبدال لوحة الإدارة الهيكلية في `src/pages/dashboard/AdminDashboard.tsx` بلوحة عملية تعرض إجمالي المدارس، وطلبات المدارس المعلقة، وإجمالي المستخدمين، والمستخدمين النشطين. وتستمع اللوحة إلى مجموعتي `schools` و`users` مباشرة عبر Firestore، وتعرض آخر طلبات المدارس المعلقة مع رابط سريع إلى شاشة الإدارة.

## ملاحظة النشر

لن تظهر لوحة الإدارة الفعلية إلا للحساب الذي يحمل الدور `admin` وفق قواعد Firestore. بعد نشر القواعد، نفّذ من جذر المشروع:

```bash
firebase deploy --only firestore:rules
```

إذا لم تكن قاعدة Firestore `(default)` منشأة بعد في مشروع `mukhtaruv`، يجب إنشاؤها مرة واحدة من Firebase Console؛ هذا الإجراء مستقل عن الكود ولا ينبغي إنشاء قاعدة مخصصة جديدة للتطبيق.

## تحديث المصادقة عبر رابط البريد — 2026-08-21

تم استبدال مسار التسجيل المسبب لشاشة المصادقة الفارغة (Google popup وكلمة المرور في التسجيل) بتدفق مبسط يعتمد على الاسم والبريد ورقم الهاتف فقط. تُحفظ المسودة محلياً بصيغة آمنة، ثم يُرسل رابط دخول/تحقق عبر `sendSignInLinkToEmail`. بعد فتح الرابط يُعالج المسار `/auth/email-link` ويُعاد المستخدم إلى `/onboarding` لإكمال الدور والمدرسة والصف، ثم تُمسح المسودة بعد نجاح حفظ الملف الشخصي.

تمت إضافة رسائل واضحة للأخطاء التالية: النطاق غير المسموح، مزود Email Link غير المفعّل، البريد غير الصحيح، الرابط المنتهي أو المستخدم، وتجاوز المحاولات. كما أُعيد `authDomain` إلى نطاق Firebase الأصلي في إعداد المشروع؛ لا ينبغي استبداله بنطاق المعاينة. رابط المعاينة يجب أن يُضاف في Firebase ضمن **Authentication > Settings > Authorized domains**، ويجب تفعيل **Email/Password provider ثم Email link** ضمن **Authentication > Sign-in method**.

نتائج التحقق: `npm run lint` ناجح، و`npm run build` ناجح، و`git diff --check` ناجح. تم التحقق بصرياً من صفحتي `/register` و`/login` في المعاينة؛ تظهر حقول الاسم والبريد والهاتف في التسجيل، ويظهر البريد وزر إرسال رابط الدخول في تسجيل الدخول، ولا يظهر زر Google أو حقل كلمة المرور.

ملاحظة تشغيلية: Firebase لا يسمح بتجاوز قائمة Authorized Domains من داخل كود الواجهة. لذلك يجب إضافة نطاق المعاينة الحالي يدوياً، أو استخدام نطاق الإنتاج النهائي بعد نشر التطبيق. إعداد Email Link لا يلغي شرط النطاق المسموح، لكنه يلغي مشكلة نافذة Google المنبثقة التي كانت تظهر فارغة.


## تحديث إدارة المدرسة والتحكم المركزي — 21 أغسطس 2026

أضيف إلى لوحة مدير المدرسة مركز تشغيل فعلي مرتبط بقاعدة Firestore الافتراضية `(default)`. يتيح المركز إنشاء الصفوف والشعب، وتحديد الغرفة، وعرض طلاب ومعلمي المدرسة، وتعيين معلم أو أكثر للمادة والشعبة، وضبط عدد الحصص اليومية ومدة الحصة وفترة الراحة وأيام الدوام.

أضيف كذلك تبويب **التحكم الأكاديمي** للمدير، ويشمل تحديد حالة الدرس في منهج الصف (مقرر، محذوف، أو مطلوب للمراجعة) وجدولة الاختبارات المركزية حسب الصف والشعبة والتاريخ والمدة والنوع. كما تم تمكين واجهة المعلم من إنشاء الاختبار الشهري وإضافة `schoolId` و`questions` إلى سجل الاختبار بما ينسجم مع قواعد Firestore الحالية.

تم تشديد قواعد Firestore لكي تكون سجلات `contentOverrides` و`schoolSettings` و`schoolClasses` و`teacherAssignments` و`schoolExams` مقيدة بالمدرسة. المدير أو الأدمن يدير قرارات المحتوى والاختبارات المدرسية، بينما يقتصر إنشاء الاختبار الشهري على معلم مصادق مرتبط بالمدرسة. كما تم منع تعديل المستخدم لدور حسابه أو تغيير مدرسته من خلال قواعد `users`.

تم توسيع زر **البيانات التجريبية** في مركز الأدمن ليُنشئ حزمة مترابطة تشمل مدرسة تجريبية، إعدادات الدوام، صفين، ثلاثة معرفات طلاب بأسماء رباعية، تعيين مادة، قرار محتوى، اختباراً مدرسياً، دعوة مدير، دعوة معلم، وحدثاً في التقويم. البيانات التجريبية تحمل `isDemo: true` لتسهيل تمييزها وحذفها لاحقاً.

### نتيجة التحقق

نجحت الأوامر التالية:

```text
npm run lint
npm run build
 git diff --check
```

تم إنشاء ملفات PWA بنجاح. يظهر تحذير Vite غير حاجب بشأن كِبر حزمة JavaScript الرئيسية، ويوصى لاحقاً باستخدام code-splitting. لم يتم نشر قواعد Firestore إلى مشروع Firebase لأن Firebase CLI غير مثبت ومستخدم البيئة غير مسجل دخوله؛ يجب تنفيذ النشر من حساب مالك المشروع بعد مراجعة القواعد:

```bash
firebase deploy --only firestore:rules --project mukhtaruv
```

يجب تنفيذ النشر بعد التأكد من أن قاعدة البيانات المستخدمة هي `(default)`، ومن أن حساب الأدمن في Firebase يملك صلاحية نشر القواعد. لا تستخدم زر البيانات التجريبية في قاعدة إنتاجية إلا بعد أخذ نسخة احتياطية، لأنه ينشئ سجلات جديدة كل مرة يُضغط فيها.


## تحديث أمني — حراسة مسارات الأدوار

أضيفت حراسة واجهة موحدة لمسارات الأدمن والمدير والمعلم والطالب وولي الأمر. إذا حاول مستخدم مصادق فتح مسار دور آخر مباشرة، يعاد إلى لوحة دوره، وإذا لم يكتمل ملفه يعاد إلى `onboarding`. تبقى قواعد Firestore هي طبقة الحماية الأساسية التي تمنع الكتابة غير المصرح بها حتى لو تم تجاوز الواجهة.

بعد ذلك نجحت مجدداً أوامر `npm run lint` و`npm run build` و`git diff --check`. التحذير الوحيد هو تحذير حجم الحزمة الرئيسية من Vite، وهو تحسين أداء لاحق وليس خطأ تشغيلياً.


## التحديث النهائي: حساب المالك وإدارة المنهج

تم تثبيت حساب المالك على البريد المحدد في إعدادات التطبيق دون تخزين كلمة المرور داخل الشيفرة. تسجيل الدخول يتم عبر Firebase Authentication، وتغيير كلمة المرور من صفحة الضبط يتطلب إعادة التحقق من كلمة المرور الحالية. كما تمت إزالة الدخول التجريبي الذي كان يمنح صلاحيات غير حقيقية.

أضيف مدير المناهج إلى مركز تحكم المالك. يدعم المدير رفع كتاب PDF وملف JSON أو Manifest إلى Firebase Storage، وإنشاء سجل خفيف في مجموعة `curriculumBooks`، وإبقاء الإصدار الجديد في حالة `pending` حتى يعتمد المالك نشره. يمكن اعتماد الكتاب أو إيقافه أو رفع إصدار بديل وتعطيل الإصدار السابق مع حفظ سجل التدقيق.

تصفّي خدمة المناهج الكتب المرسلة إلى الطالب بحيث لا يظهر إلا الكتاب النشط والمعتمد. الكتب الرسمية يمكن تقسيمها حسب `gradeKey` و`subject` و`part`، وتبقى ملفات PDF وJSON خارج Firestore لتقليل حجم القاعدة، بينما يحتفظ Firestore بالفهارس والروابط وبيانات الإصدار.

نجحت الفحوصات النهائية: `npm run lint` و`npm run build` و`git diff --check`. ظهرت ملاحظة أداء غير حاجبة من Vite حول حجم الحزمة الرئيسية، ويوصى لاحقاً بتقسيم التحميل إلى مسارات lazy-loaded.

لم تُرفع جميع ملفات المناهج تلقائياً إلى مشروع Firebase أثناء الفحص؛ الرفع الفعلي يحتاج تنفيذ أداة المزامنة من بيئة موثوقة تحتوي بيانات اعتماد Firebase Admin، ثم نشر القواعد بعد مراجعتها. لا ينبغي وضع مفتاح خدمة Firebase أو كلمة مرور المالك داخل المستودع أو ملفات الواجهة.

### خطوات الإنتاج الموصى بها

```bash
firebase deploy --only firestore:rules,storage --project mukhtaruv
node scripts/sync-curriculum.mjs --manifest data/curriculum_manifest.json --project mukhtaruv
```

يجب تشغيل أداة المزامنة بعد ضبط حساب خدمة Firebase في متغير بيئي آمن، ومراجعة سجل العملية قبل إتاحة الكتب للطلاب. بعد الرفع، يعتمد المالك الكتب من مركز التحكم؛ لا يتم نشر الكتاب للطلاب بمجرد رفعه.
