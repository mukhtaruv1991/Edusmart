# تقرير تسليم دمج المناهج — EduSmart AI Connect

**التاريخ:** 27 أغسطس 2026

## النتيجة التنفيذية

تم اعتماد مسار موحد يعتمد على **Firestore database ID = `default`** دون إنشاء قاعدة إضافية ودون استخدام Firebase Storage، لأن حساب الفوترة المرتبط بالمشروع مغلق. بهذا لا يحدث تشتت بين قواعد بيانات متعددة: تبقى حسابات المستخدمين، المدارس، الصفوف، الصلاحيات، فهرسة المناهج، ونصوص الصفحات داخل Firebase الحالي.

## ما تم إنجازه

| البند | الحالة والنتيجة |
|---|---|
| المصادر | جرد روابط الكتب الرسمية للصفوف 7–12 في ملفات المشروع، مع حفظ الرابط الرسمي لكل كتاب |
| التنزيل | 105 ملفات PDF سليمة محليًا في آخر دفعة مكتملة، مع استمرار جولة تنزيل إضافية للملفات التي يقطعها الخادم |
| المعالجة | إنشاء مخرجات JSON صفحةً بصفحة ونص كامل وبيانات وصفية للكتب المكتملة |
| Firestore | فحص نهائي: 112 سجل كتاب، منها 106 سجلات صالحة لمسار Firestore-only، و107 وثائق chunks نصية |
| القارئ | `loadBookPages` يقرأ manifest عند وجوده، أو يقرأ `curriculumBooks/{bookId}/contentChunks` عند `contentMode = firestore_chunks` |
| PWA | نجح `pnpm build` وتوليد ملفات PWA دون أخطاء بناء؛ بقي تحذير حجم الحزمة فقط |
| GitHub | آخر commit مدفوع: `f707b21` على الفرع `main` في مستودع `mukhtaruv1991/Edusmart` |

## طريقة التشغيل الحالية

يحوي سجل `curriculumBooks` بيانات الصف والمادة والجزء وعدد الصفحات والبصمة والرابط الرسمي، مع `contentMode: firestore_chunks` و`contentChunkCount`. ويحوي المسار الفرعي `contentChunks` دفعات صفحات نصية أقل من الحد الآمن لوثيقة Firestore. عند فتح كتاب، يقرأ القارئ هذه الصفحات ويستطيع استخدامها للبحث والشرح والتلخيص وتوليد الأسئلة وفق واجهة التطبيق الحالية.

لا تُخزّن ملفات PDF نفسها داخل Firestore؛ إذ تبقى في رابط المصدر الرسمي. لذلك يعمل النص المعالج داخل التطبيق، بينما عرض PDF يعتمد على توفر رابط الوزارة. هذا المسار لا يضمن تنزيل PDF دون اتصال ولا يضمن بقاء المصدر الخارجي متاحًا إذا غُيّر الرابط.

## القيود والخطوة المطلوبة من مالك المشروع

تم تعديل `firestore.rules` لإضافة قبول الكتب ذات المحتوى المجزأ والسماح بقراءة `contentChunks` للكتاب النشط والمعتمد. محاولة نشر القواعد آليًا فشلت لأن حساب الخدمة لا يملك صلاحية تفعيل `firestore.googleapis.com`؛ يجب على مالك المشروع نشر ملف `firestore.rules` من Firebase Console أو منح الحساب صلاحية إدارة قواعد Firestore. هذا لا يتطلب إنشاء قاعدة بيانات جديدة.

يوجد ستة سجلات قديمة لا تطابق صيغة Firestore-only، وقد أبقيت خارج عداد الكتب الصالحة بدل حذفها تلقائيًا. كما أن خمسة ملفات جزئية قد تبقى مرتبطة بانقطاعات المصدر، وتستمر أداة التنزيل المجزأ في محاولة استئنافها.

## الملفات المهمة

| الملف | الوظيفة |
|---|---|
| `scripts/preprocess_official_curriculum.py` | استخراج النص وبناء الصفحات والبيانات الوصفية |
| `scripts/sync-curriculum-firestore-only.mjs` | مزامنة metadata وchunks إلى Firestore `default` دون Storage |
| `scripts/verify_firestore_curriculum.mjs` | التحقق من عدد الكتب وchunks دون عرض المحتوى |
| `src/lib/curriculumService.ts` | تحميل الصفحات من manifest أو Firestore chunks |
| `firestore.rules` | قواعد الكتب وقراءة `contentChunks` |
| `docs/curriculum_integration.md` | توثيق بنية التكامل ومسار عدم توفر Storage |

> **تنبيه أمني:** ملف Service Account موجود محليًا فقط ومُستبعد من GitHub. لا ينبغي نشره أو إرساله إلى أي جهة عامة.
